# MBTI Jump — 設計文件

- 日期：2026-06-30
- 狀態：已通過 brainstorm，待寫實作計畫

## 一句話描述

一款類經典 Doodle Jump 的手機網頁遊戲，玩家持續向上彈跳，途中穿插 MBTI 題目；題目以「左 Yes / 右 No」的分叉台階呈現，跳哪邊就是選哪邊。四大關各對應一個 MBTI 維度，累計偏向後拼出完整人格類型。

## 目標與範圍

### 平台與分發
- **手機網頁（Mobile Web）**，直式（portrait）操作。
- 分享連結即玩，瞄準 MBTI 類測驗的社交傳播特性。

### MVP 範圍
- **純前端、無後端**，可部署到 Vercel / Cloudflare Pages 等靜態主機。
- 結果在前端算完直接顯示 + 分享，不需帳號、不需排行榜、不需資料庫。

### 明確不做（YAGNI）
- 後端 / 帳號 / 歷史紀錄 / 排行榜（之後版本再議）。
- 正式美術精靈圖（MVP 用程式美術）。
- 音效系統、成就系統、多語系（之後版本再議）。

## 技術選型

- **Vite + TypeScript**：直式手機、靜態部署、熱重載快。
- **Phaser 3**：2D 網頁遊戲界資料量最大、最成熟的引擎，內建重力/碰撞/場景/攝影機。
  - 選它的核心理由：開發便利 + 參考資料最多 → AI agent 寫出正確程式碼的可靠度最高。
  - bundle gzip 後約 250–350KB，現代手機網頁可接受。
- **操控**：重力感應（DeviceOrientation）控制左右移動，附「點擊螢幕左/右半邊」作為備援（iOS 體感權限被拒或不支援時）。

## 核心玩法

### 結構：逐關上爬、答完即過關
- 玩家角色持續往上跳（重力 + 自動彈跳），側傾手機控制水平移動。
- 平台兩種：
  - **普通平台**：隨機散布，提供經典彈跳手感與節奏。
  - **分叉題目平台**：到一定高度出現，左塊寫 **Yes**、右塊寫 **No**，中間留空隙。跳哪邊 = 選哪個答案，落地當下記錄。
- 一關 = 一個維度，關內有固定題數的同維度問題。答完該關題數 → 場景轉換 → 進下一關。
- 四關走完 → 結算頁。

### 維度對應（一關一維度，累計偏向）
- 關 1 = E/I（外向 / 內向）
- 關 2 = S/N（實感 / 直覺）
- 關 3 = T/F（思考 / 情感）
- 關 4 = J/P（判斷 / 感知）

每關內，玩家每次落在 Yes/No 台階就替對應字母 +1；關末（或全程末）比較兩邊次數決定該維度字母。四個維度拼出 4 碼人格類型。

### 掉落處理
- **掉出畫面 = 遊戲結束，但保留已過關進度（checkpoint per level）**。
- 重來只重玩「當前關」，已答完的維度結果不消失。

### 結算
- 顯示 4 碼人格類型（例：`ENFP`）。
- 一段簡短人格說明文字。
- 分享按鈕（MVP 可先做「複製連結 / 複製結果文字」，純前端）。

## 架構與模組切分

```
src/
  main.ts                 # Phaser 遊戲啟動、全域設定（portrait、縮放）
  config/
    questions.ts          # 四維度題庫（純資料，與遊戲邏輯解耦）
    gameConfig.ts         # 重力、跳躍力、平台間距、每關題數等可調參數
  core/
    ScoreTracker.ts       # 累計各維度兩邊次數 → 算出 4 碼結果（純函式、可單測）
    Controls.ts           # DeviceOrientation → 水平加速度，附點擊左右半邊備援
  scenes/
    BootScene.ts          # 載入資源、要求體感權限(iOS)、開始畫面
    GameScene.ts          # 主玩法：角色、平台生成、彈跳物理、分叉題目、掉落判定
    LevelTransitionScene.ts # 過關動畫 + 下一維度提示
    ResultScene.ts        # 結算：4 碼類型、說明、分享
  entities/
    Player.ts             # 玩家角色（彈跳、左右移動、攝影機跟隨）
    Platform.ts           # 普通/題目平台，題目平台帶 Yes/No 標籤與維度方向
  ui/
    QuestionBanner.ts     # 接近分叉時於上方顯示當前題目文字
```

### 關鍵解耦
- `ScoreTracker` 與 `questions.ts` 為純資料 / 純邏輯，不依賴 Phaser，可獨立單元測試。
- 遊戲場景只負責「呈現 + 把落點回報給 ScoreTracker」。
- 換正式美術只需替換貼圖資源，不動遊戲邏輯。

## 資料結構：題庫

```ts
type Dimension = 'EI' | 'SN' | 'TF' | 'JP';

interface Choice {
  label: string;   // 台階上顯示的選項文字
  side: 'E'|'I'|'S'|'N'|'T'|'F'|'J'|'P'; // 跳這邊加給哪個字母
}

interface Question {
  dimension: Dimension;
  text: string;    // 題幹
  yes: Choice;     // 左側台階
  no: Choice;      // 右側台階
}
```

範例：
```ts
{
  dimension: 'EI',
  text: '週末你比較想…',
  yes: { label: '揪一群人出去', side: 'E' },
  no:  { label: '在家充電',     side: 'I' },
}
```

- MVP：每關 **5 題**，共 20 題，全程約 2–3 分鐘。
- **每關題數刻意取奇數**：Yes/No 次數加起來為奇數，維度字母必定有結果，永遠不會平手，MVP 因此不需要 tie-break 機制。

## 美術範圍（MVP）

- 程式美術：簡潔幾何 + emoji / 純色塊，乾淨好讀。
- 直式畫面、單手可玩。
- 之後升級正式精靈圖時，僅替換貼圖，不動邏輯。

## 測試策略

- **純邏輯單元測試**：`ScoreTracker`（累計、平手處理、四碼輸出）、題庫資料完整性（每題 dimension 與 side 對應正確）。
- 遊戲場景以手動 / 視覺驗證為主（Phaser 場景互動較難自動化）。
